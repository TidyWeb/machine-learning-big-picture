Machine learning:
the big picture

Machine learning uses examples to learn a pattern. The kind of answer we want determines the kind of task—and that points us towards an algorithm.

ExamplesRows of recorded cases, such as past house sales
→
Learning methodAn algorithm works on chosen information and, where available, known answers
→
Learned modelA pattern used to estimate an answer or find structure in new cases

The picture applies to supervised and unsupervised learning; the information supplied and the result differ.

After this guide: you should be able to distinguish an example, its features, the target, possible categories and a known label—and see how those pieces change between supervised and unsupervised learning.

01AI and ML
Question 1

What is artificial intelligence, and where does machine learning fit?

Artificial intelligence (AI) is a broad area concerned with computers doing tasks that seem to require abilities such as recognising patterns, understanding language, making predictions, or choosing actions.

Machine learning (ML) is one way to build some AI systems: the computer learns a pattern from examples rather than following only a complete list of hand-written rules. Not every AI system uses machine learning, and machine learning is not a mind. It is a set of methods that learn patterns from data for a defined task.

02The purpose
Question 2

What does a machine-learning system learn from data?

It adjusts a mathematical model so that it captures a pattern in example data. We then use that fitted model to estimate an answer or find structure in cases it has not seen before.

For example, records of past house sales might help a model estimate the likely sale price of a new house. The computer does not understand property as a person does: its result depends on the examples, features, and learning method we supply.

examples→learning method→fitted model→answer or pattern
03Example
Question 3

What is one example, instance, observation, or record?

These names usually mean one case being described. In our table, House A is one example of a house sale. The whole row belongs to that one case; each column tells us something about it.

ONE EXAMPLE · ONE ROW
House AArea: 72 m²Bedrooms: 2Age: 18 yearsType: flat

All four recorded details describe the same house sale.

So an example is the case, not just one value in the row. House A's area alone is one piece of information about the example.

04Feature
Question 4

What is a feature?

A feature is a piece of information about an example that we give the model as an input—a clue it can use. For a house, area, bedrooms, age, and location could all be features.

ONE HOUSEINPUT FEATURES · CLUES
Area72 m²
Bedrooms2
Age18 years
LocationBirmingham

A feature can be a number, such as area, or a category, such as location. The same column can play different roles in different tasks: property type could be a feature when predicting price, but it becomes the target when property type is what we want to predict.

Quick distinction: the example is the whole case; a feature is one input detail describing that case.

05Target
Question 5

What is the target, and how is it different from a feature?

The target is the answer we want the model to learn to predict. Features are the input clues; the target is the answer side of the question.

QUESTION A · ESTIMATE A NUMBERFeatures: area, bedrooms, ageTarget: sale priceExample target value: £210,000
QUESTION B · CHOOSE A CATEGORYFeatures: area, bedrooms, ageTarget: property typeExample target value: flat

The rows and clues can stay the same while the question changes. If price is the answer we want, price is the target. If property type is the answer, property type is the target.

06Categories
Question 6

What is a category, and what are the categories in a classification task?

A category is one named kind of answer. In classification, the task is to choose among a set of possible categories. Those possible categories are also called classes.

POSSIBLE ANSWERS · CATEGORIES / CLASSES
FlatHouse

This question has two possible categories. A different task might have many: for example, flat, terraced house, semi-detached house, and detached house.

The model does not decide what the categories mean. People define them in the task and data. A category is the kind of answer available; one property's known answer will be one particular category.

A category can also appear as an input feature. For example, location could be a feature while sale price is the target.

07Label
Question 7

What is a label, and how does it relate to a category and a target?

In supervised classification, a label is the known correct category recorded for one example. “Flat” and “house” are the possible categories; House A's known label is “flat.” The category is the possible kind of answer; the label is the answer attached to this particular example.

EXAMPLEFEATURE CLUESKNOWN LABEL
House A72 m² · 2 bedroomsFlat
House B96 m² · 3 bedroomsHouse
New house101 m² · 3 bedroomsNot known yet

The model learns from the first two rows: their feature clues are paired with known labels. For the new house, its features are available but its correct label is not; predicting that label is the job.

Target is the broader term for the answer being predicted. When the target is a category, people commonly call it the label. For a number such as sale price, we usually say target value rather than label.

08Task types
Question 8

How does the kind of answer we need determine the ML task?

Start with the human question, then identify the kind of answer it needs. That gives us the task family before we choose an algorithm.

A number → regression

Estimate a house price, delivery time, or amount of sales.

A known category → classification

Predict flat/house, spam/not spam, or another named class.

Unlabelled groups → clustering

Find examples that are similar without pre-supplied group names.

Unusual cases → anomaly detection

Identify records that differ from the pattern considered normal.

Forecasting adds an important time-order question: future values must be predicted from earlier information. Reinforcement learning is a different setup where an agent learns actions from rewards or penalties.

09Learning setup
Question 9

What is the difference between supervised and unsupervised learning?

Use the same property clues, but change whether the known answer is supplied:

SUPERVISED · KNOWN ANSWERS INCLUDED

Training row: 72 m² · 2 bedrooms + label: flat

The model learns how feature clues relate to known target answers. For a new row, it predicts the missing answer.

UNSUPERVISED · NO ANSWER COLUMN

Input row: 72 m² · 2 bedrooms no supplied label

A clustering method groups rows by their features. A result such as cluster 0 is a group ID, not a known category like “flat.”

“No labels” means no correct target answers were supplied for learning. It does not mean the feature columns cannot contain categories, and it does not mean that people make no choices: people still select data and features and interpret the result.

10Algorithm and model
Question 10

What is an algorithm, and how is it related to a fitted model?

An algorithm is the method or set of steps used to learn from data. The fitted model is the learned pattern or structure produced after those steps have been applied to particular examples.

For instance, K-means is an algorithm. After fitting it to chosen features, we have the resulting cluster assignments and centres. In casual conversation, “model” is sometimes used for both the method and its fitted result; notice which meaning is intended.

11Whole workflow
Question 11

What is the usual route from a business question to a model result?

Work from the problem towards the method. Decide what result would be useful, find suitable data, define the examples and features, establish whether there is a target, then prepare the data and select a method. Fit the method, evaluate the result, and interpret whether it helps with the original question.

01 · QUESTION

What decision or answer is needed?

02 · DATA

Find relevant, suitable examples.

03 · REPRESENT

Choose features and a target if supplied.

04 · LEARN

Select and fit an algorithm.

05 · CHECK

Evaluate it with fair evidence.

06 · USE

Interpret and monitor the result.

The algorithm is one part of this workflow. It cannot repair an unclear goal or make unsuitable data meaningful by itself.

12Data splits
Question 12

In supervised prediction, what do training, validation, and test data each do?

Training data teaches the model. Validation data helps compare models or settings while developing the solution. A separate test set is held back for a final check after those choices are settled.

Test examples stand in for cases the model has not seen. If we keep using the test result to adjust our choices, it stops being an independent final check. The split should also match the real situation: time-ordered data, repeated people, or related records may need special splitting rules.

13Cross-validation
Question 13

What is cross-validation, and why use it?

Cross-validation repeats the train-and-validate process across several different splits of the available development data. In k-fold cross-validation, the data is divided into folds; each fold takes a turn as the validation portion while the others are used for fitting.

This gives a more rounded view than relying on one fortunate split and helps compare settings. It does not replace a final untouched test set, and the split design must respect the data—for example, a random split can be misleading for time series or records from the same person.

14Fit and generalise
Question 14

What are overfitting, underfitting, and the bias–variance trade-off?

Overfitting means the model has learned quirks of its training examples so closely that it performs worse on new cases. Underfitting means the model is too limited or insufficiently trained to capture even useful patterns.

Bias describes errors from a model that is systematically too simple; variance describes how much its learned result changes with the particular training sample. A very complex model may have low training error yet vary sharply between samples. We use validation and suitable model constraints to seek a balance that generalises.

15Leakage
Question 15

What is data leakage, and how can it make a model look better than it is?

Data leakage happens when information that would not really be available at prediction time slips into model building or evaluation. The result can look impressively accurate in development and then fail on genuinely new cases.

A common route is to let the test data influence preprocessing or model choices. For example, a scaler should learn its averages and spreads from training data, then apply that same transformation to validation or test data. A pipeline can keep preprocessing and model fitting together inside each training split.

16Metrics
Question 16

What does a performance metric tell us, and why must it match the task?

A metric turns a model’s errors or successes into a summary number. For a price estimate, mean absolute error or root mean squared error describes prediction error in money units. For classification, accuracy counts overall correct decisions, while precision and recall answer different questions about positive predictions and missed positives.

There is no universally best metric. If one class is rare or one kind of error is more costly, accuracy alone may hide the problem. Choose a metric based on what a wrong prediction means in the real task, and inspect more than one view when needed.

17Prediction and cause
Question 17

Does a useful prediction prove that one thing caused another?

No. A model may find that two things move together and use that relationship to predict, but that alone does not establish that one caused the other. A house feature may be associated with price because of other factors we have not measured.

When the question is “Did this change cause a difference?”, a well-designed experiment such as an A/B test can provide stronger causal evidence because it deliberately compares randomly assigned groups. Prediction and causal analysis answer different questions, though they can sometimes support one another.

18Choose a method
Question 18

How do we choose a suitable algorithm?

First clarify the output and the decision it should support. Then consider the shape and size of the data, how much preparation it needs, the kinds of errors that matter, how explainable the result must be, and whether the method’s assumptions make sense for the problem.

Start with a sensible baseline—a simple reference result—so that a more complicated model has something meaningful to beat. Compare candidates using the same fair data splits and task-relevant metrics. After a model is put into use, monitor whether the data or real-world task changes. “More advanced” or “more accurate on training data” does not automatically mean more suitable.

19Linear regression
Question 19

How does linear regression predict a number?

Linear regression estimates a numerical target by fitting a straight-line relationship between the inputs and the known answers. With one feature, imagine drawing a line through house area and sale price so that the predictions are reasonably close to the known prices. With several features, the relationship is a flat surface in a higher-dimensional space, though we cannot draw that whole shape on a simple page.

The fitted coefficients describe how the model combines features to produce its estimate. They describe patterns in the data; they do not by themselves prove causes. Linear regression is useful as a clear starting model, while strongly curved or more complicated patterns may need other methods.

20Logistic regression
Question 20

Why is logistic regression usually a classification method?

Logistic regression estimates the probability of a category, such as the chance that a property is a house rather than a flat. A threshold or another decision rule can turn that probability into the final class.

Despite its name, it is generally used for classification, while linear regression predicts a number. The name comes from the mathematical form used to model the probability. The threshold should reflect the task: missing a positive case and raising a false alarm can have different costs.

21Decision trees
Question 21

How does a decision tree make a prediction?

While fitting, a decision tree searches for questions about features that divide the training examples into more useful groups. For a new house, the tree asks those questions in order and follows the matching branch. The path ends at a leaf, which gives a predicted category or number.

FEATURE QUESTIONArea above this value?
→
BRANCHFollow the matching answer
→
LEAFPredicted class or value

Trees are often easy to picture, but very deep trees can memorise exceptions. The maximum depth and other settings control how much detail the tree can learn.

22Tree ensembles
Question 22

How do bagging, random forests, and boosting combine trees?

An ensemble combines several models. Bagging builds models from varied samples and combines their predictions. A random forest is a tree ensemble in this family: it adds randomness in the features considered for splits, helping make trees less alike.

Boosting builds trees in sequence. Each new tree helps correct weaknesses in the ensemble so far. Bagging gathers varied opinions; boosting builds a chain of improvements. Both can predict categories or numbers, but their training procedures and behaviour differ.

23Neural networks
Question 23

What is a neural network, and what is a perceptron?

A neural network is a model made of connected calculation units arranged in layers. A perceptron is one simple unit: it multiplies each input by a weight, adds an adjustable offset called a bias, then passes that score through an activation function to produce an output.

In the classic supervised perceptron rule, the unit compares its prediction with a known label. If it is wrong, the weights are adjusted so that this example is more likely to get the correct answer next time; the size and direction of each change depend on the input, the mismatch and the step size. This unit bias shifts its cutoff; it is different from bias in the bias–variance trade-off. This connects to both hands-on builds in this project: the spreadsheet exercise follows its named Hebbian association rule, while the letter classifier demonstrates a supervised mistake-driven correction. They illustrate related ideas, but use different update rules.

For one perceptron, an activation such as a step rule turns the score into a yes-or-no decision. In a network with stacked layers, non-linear activation functions between layers let the network learn more complex patterns: without them, stacked weighted sums collapse into one linear transformation. Training changes the weights: in a multilayer network, backpropagation estimates how each weight affects error, and gradient descent repeatedly nudges weights to reduce it. Running a fitted network passes an input through it using the learned weights without changing them.

24Images and text
Question 24

How can machine learning work with images and text?

Most algorithms need numerical inputs. An image can be represented by pixel values; text can be represented by counts, weighted word features, or richer numerical representations. Turning raw material into useful numbers is called feature extraction.

A convolutional neural network (CNN) is a neural-network design often used for images. It learns small visual patterns and combines them into larger patterns. Text methods can classify documents, group similar documents, or retrieve items by meaning. These tasks use the same big picture—examples, features, method, result—but need representations suited to the material.

25Quick wins
Question 25

What makes a good early machine-learning project or “quick win”?

A good starting project has a real, bounded question, useful historical data, a result someone can act on, and a way to check whether it helped. Examples include suggesting relevant documents, routing common help-desk requests, finding similar text, or estimating demand from existing reports.

Start with the available data and the ideal outcome, then test a simple route before building a complex model. A system that saves staff time or helps people find information may be useful even when it does not use a sophisticated algorithm. Check the result with people who understand the work.

26Clustering
Question 26

What does clustering try to discover?

Clustering groups examples that are similar according to chosen features and a chosen notion of distance or density. It is an unsupervised task because the examples do not arrive with the group names we hope to discover.

The algorithm gives assignments, not meanings. If houses land in three clusters, that does not automatically mean “starter homes”, “family homes”, and “large homes”. Inspect the actual houses and describe the differences before giving groups a real-world interpretation.

27Feature space
Question 27

What does “near” mean in clustering, and why do feature choice and scale matter?

Each example becomes a point whose coordinates are its chosen feature values. “Near” is calculated from those coordinates using a distance measure. Choosing area and bedrooms asks a different grouping question from choosing area, bedrooms, and age.

Scale can change distances dramatically. If prices are in hundreds of thousands while bedrooms are single digits, the price dimension can dominate. Scaling puts features on comparable scales, but it cannot decide which features are meaningful. Outliers and irrelevant columns can also distort the geometry.

When a dataset has many columns, PCA can create a lower-dimensional view that helps us inspect patterns. PCA changes the representation; it does not assign clusters or prove that groups exist.

28K-means
Question 28

What is the key idea and repeating cycle behind K-means?

K-means forms a chosen number of groups by alternating two actions: give every point to its nearest centre, then move each centre to the average position of the points assigned to it. The centres are called centroids.

01 · SET K

Choose how many groups to try.

02 · START

Place K initial centres.

03 · ASSIGN

Send each point to the nearest centre.

04 · UPDATE

Move each centre to its group mean.

05 · REPEAT

Stop when assignments settle.

The word “means” refers to the average positions used to update the centres. The result depends on the chosen features, their scaling, K, and the starting positions.

29K and diagnostics
Question 29

How do we choose K, and what do inertia, the elbow, and silhouette tell us?

K-means requires us to choose K, the number of groups. Inertia measures how close points are to their assigned centres. It normally falls as K increases, so inertia alone cannot tell us the best number. The elbow method looks for a point where the improvement begins to level off.

Silhouette compares how close each point is to its own cluster with how close it is to a neighbouring cluster. It is a clue about separation, not a certificate that the groups are real or useful. Inspect individual cluster distributions as well as the overall average.

Starting centres can change the result. k-means++ spreads initial centres out more thoughtfully, and trying several starts can reduce the risk of an unlucky run. K-means can still mislead when there are no natural groups, when groups are curved or stretched, or when extreme rows pull centres. These techniques improve the search; they do not prove K is correct.

30DBSCAN
Question 30

How does DBSCAN find clusters, and what do its point roles mean?

DBSCAN grows clusters from dense areas: places where enough points are close together. You set EPS, the neighbourhood radius, and min_samples, the number of nearby points needed for a dense point. In scikit-learn, the count includes the point itself.

A core point has enough neighbours and can extend a cluster. A border point lies near a core point but is not itself dense enough to extend the cluster. A noise point does not join a cluster and is labelled -1 in scikit-learn. DBSCAN can find irregular shapes and mark noise without choosing K, but a single EPS can struggle when groups have very different densities.

31HDBSCAN
Question 31

What does HDBSCAN add, and when can it be more useful than K-means or DBSCAN?

HDBSCAN examines how groups appear across a range of density levels, then selects clusters that remain stable across that range. It avoids requiring one fixed EPS value and can handle datasets where useful groups have different densities better than a single-setting DBSCAN run.

This makes HDBSCAN a strong candidate when K is unknown, group shapes are irregular, or one density setting does not describe all groups well. It still has choices such as min_cluster_size (the smallest group worth keeping) and min_samples (how conservatively dense points are defined). It can mark observations as noise, and it may leave small groups out.

Why “more useful” depends on the data

HDBSCAN can be more useful when groups vary in density. K-means can be simpler and faster for compact groups; DBSCAN can be a clear first density-based method when one EPS works. Test the assumptions against the shape and purpose of your data.

32Interpret clusters
Question 32

How do we judge clusters and choose between clustering methods?

First inspect the assignments, group sizes, feature profiles, noise points, and stability when settings or samples change. Internal measures such as silhouette describe aspects of separation, but may prefer particular shapes and do not explain real-world meaning. If reliable known labels exist, they can support a separate comparison, but clustering itself did not learn from those labels.

Then ask whether the groups help with the original purpose. A cluster number such as 0 or 1 is only an arbitrary handle; it does not name a customer type. PCA or a two-feature plot may help people look at a high-dimensional result, but a projected picture can hide structure and must not replace checks in the actual feature space.

Check the geometry

Do the points separate under the chosen representation and distance or density rule?

Check the meaning

Can we describe the groups from their features, and do those descriptions help the real task?

Other families offer different assumptions: hierarchical clustering builds nested groupings; Gaussian mixtures estimate probabilistic, often oval-shaped groups; OPTICS orders points to examine density structure across settings. These are candidates to compare, not automatic upgrades. The best result is a defensible pattern that is stable enough, understood in context, and useful for the question we set out to answer.

↺Recall

Can you recall the core ideas?

Try these first

Say your answer aloud or write a few words before opening a reveal. The point is to name each thing's job.

1. What is an example?

One whole case or record, usually one row. House A is one example; area 72 m² is only one value in that example.

2. What is a feature?

An input clue describing an example, such as its area, bedrooms, or location.

3. What is the target?

The answer the model is being trained to predict. It could be a number such as price or a category such as property type.

4. What is the difference between a category and a label?

Categories are the possible named answers, such as “flat” and “house.” A label is the known category attached as the correct answer to one training example, such as House A → “flat.”

5. What changes between supervised learning and unsupervised clustering?

Supervised training examples include known target answers. Clustering receives features without known group labels and returns group assignments that need interpretation.

6. What are the repeating steps in K-means?

Assign points to their nearest centres, move each centre to the mean of its assigned points, and repeat until the result settles.

7. How does HDBSCAN differ from DBSCAN?

DBSCAN uses one chosen EPS neighbourhood radius. HDBSCAN looks across density levels and selects stable clusters, so it can be more suitable when groups have different densities.

8. What are the main steps from a question to a supervised model result?

Clarify the answer to predict, choose useful features, and separate data for fitting and checking. Fit the learning method on training data, use validation data or cross-validation to compare choices, then check the settled approach on the untouched test set. Use the result with care and monitor it in its real setting.

9. What is the difference between a learning algorithm and a fitted model?

The algorithm is the learning procedure. It uses training examples to produce a fitted model, which is the learned pattern used to make predictions for new examples.

10. What do training, validation, and test data each do?

Training data is used to fit the model. Validation data helps compare models or settings during development. The test set is held back for a final check after those choices are settled; repeatedly tuning against it means it is no longer an independent final check.

11. Why use cross-validation, and does it replace the test set?

Cross-validation repeats fitting and validation across several splits of the development data, giving a less split-dependent comparison. It helps choose settings, but it does not replace a separate, untouched test set for the final check.

12. How do bias and variance relate to underfitting and overfitting?

High bias means a model is too limited to capture useful patterns; this often leads to underfitting, with poor results even on training examples. High variance means the learned result changes a lot with the particular training sample; this often leads to overfitting, where training results look good but new examples fare worse. These are common connections, not exact synonyms.

13. What is data leakage? Give one example.

Leakage is when information that should be unavailable during training or evaluation influences the model or its score. For example, if a scaler learns its averages and spreads from the whole dataset before the train/test split, the test data has influenced preprocessing. The test score can then look better than a genuinely independent check.

14. Why put preprocessing and a model in one pipeline object?

A pipeline keeps the preparation steps and model together in the right order. When it is fitted separately inside each training split, preprocessing learns only from that split and then transforms its validation data; cross-validation can repeat this safely for each fold. The same fitted preparation is then applied to later test or new data.

15. Why must a performance metric match the task?

Metrics answer different questions. Accuracy gives the share of correct classifications, but it can hide poor detection of a rare class—for example, when almost every case is negative. Precision tells us how often a predicted positive is correct; recall tells us how many actual positive cases we catch. For numeric predictions, measures such as MAE or RMSE describe the size of errors. Choose metrics based on the task and the cost of mistakes.

16. Why doesn’t a good prediction prove that one thing caused another?

A predictive pattern can help estimate what may happen without showing why it happens. Another factor may influence both things. To support a causal claim, we need a design that addresses alternative explanations; a carefully run randomised experiment can provide stronger evidence than prediction alone.

17. How do linear regression and logistic regression differ?

Linear regression predicts a numerical target, such as a sale price. Logistic regression estimates the probability of a category and is usually used for classification, such as flat versus house.

18. How does a decision tree make a prediction?

It asks questions about feature values, follows the matching branches, and reaches a leaf that gives a predicted category or number.

19. What is a tree ensemble, and how do random forests and boosting combine trees?

An ensemble combines several models. A random forest builds varied trees and combines their predictions. Boosting builds trees in sequence, with later trees helping correct weaknesses in the earlier ensemble. Both can predict categories or numbers.

20. What should guide the choice of an algorithm?

Start with the output you need and the decision it will support. Then consider the data, the errors that matter, the method’s assumptions, and how much explanation is needed. Compare a simple baseline and candidate methods using fair splits and task-appropriate metrics.

21. What kind of result does each task seek: regression, classification, clustering, or anomaly detection?

Regression predicts a number; classification chooses a known category; clustering groups examples that seem similar without supplied group names; anomaly detection flags cases that differ from what is typical. Anomaly detection can be approached in more than one learning setup.

22. What is a perceptron, and how does it relate to a neural network?

A perceptron is one simple weighted-input unit that uses a bias and activation function to produce an output. A neural network connects units in layers. Training adjusts their weights; running a fitted network uses those learned weights to produce an output.

23. How can a machine-learning model use images and text?

The model receives numerical representations: an image can be represented by pixel values, while text can be represented by word or token features or other numerical encodings. Feature extraction turns the original material into values a method can use.

24. What is clustering actually trying to discover?

It looks for groups of examples that are similar under selected features and a chosen distance or density rule. The assignments are just group IDs; people inspect the examples and features to decide whether the groups have a useful meaning.

25. Why does feature scaling matter when clustering uses distances?

A feature with much larger numerical values can dominate a distance calculation and drown out smaller-scale features. Scaling can put features on more comparable ranges, but it does not decide which features matter or guarantee meaningful clusters.

26. How can the elbow and silhouette help us choose K for K-means, and what are their limits?

The elbow looks for where the drop in inertia begins to slow as K grows. Silhouette compares how close examples are to their own group with how close they are to another group. Both are clues, not proof of the correct or useful K; also inspect group profiles, stability, and the purpose of the analysis.
